## Current implementation snapshot — automated verification 2026-10-04

M1 is complete. M2 code is implemented: the browser edge enumerates/selects microphones, requests speech processing off, frames PCM in an outputless AudioWorklet, reports permission/device loss, and releases tracks/nodes/contexts on stop. M3 code is also implemented at the user's explicit direction: a windowed spectral scan ranks candidates by persistence, narrowness, SNR, and duty evidence; automatic lock tracks modest drift with degraded/lost/reacquisition hysteresis; manual lock never chases a stronger neighbor; bounded pre-roll preserves the start of a message.

M5's deterministic RF-like gate is complete at the user's direction while the remaining M2/M3 hardware edge cases stay open. The seven-fixture corpus covers clean regression, broadband noise, deep fading, DC/hum/impulses, a nearby continuous carrier, a 55 Hz drifting weak tone, and loss/reacquisition at a new pitch. Compared with the measured pre-tuning baseline of 72% CER, the final aggregate is 1.22% CER, 5% WER, 85.7% exact messages, zero unknowns, zero false locks, 100% acquisition, and 100% recovery for the labeled loss. Corpus v1 is deterministic modeled audio, not over-the-air recordings; field accuracy remains unclaimed. On 2026-09-15 the user also reported a recognizable decode of a known CW transmission through the MacBook's built-in microphone.

M6 is complete at the user's direction. The debug surface is now a responsive, accessible operator interface with a dominant immutable raw transcript, plain-language capture/acquisition states, a bounded tone/space timeline, Morse marks, selectable recent characters with confidence evidence, competing-tone controls, diagnostics, and recovery help. Twenty-one browser tests, the RF benchmark, strict TypeScript checks, and the production build pass under Node 18; desktop and narrow layouts were visually inspected.
